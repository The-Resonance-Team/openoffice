# 0024 — Turborepo monorepo for CLI plus web

The repo is now a Bun-workspace monorepo driven by Turborepo: `apps/cli` (the published `openoffice` package, unchanged inside) and `apps/web` (a Next.js frontend for the daemon). The workspace root is private and carries no version. This amends ADR 0001, which chose a single package "not a monorepo" — that reasoning still holds for the CLI's internals, and `apps/cli/src/` keeps its flat domain layout and deep-module boundaries exactly as ADR 0001 describes. What changed is that a second deployable appeared with a different runtime, a different build tool, and no shared types, which is the "actually needs it" condition ADR 0001 left open.

The two apps deliberately share nothing. The web app writes its own DTOs against the daemon's HTTP surface rather than importing types from `apps/cli`, so there is no `packages/*` tier and no build-order coupling — the cost is DTO drift when the daemon's API changes, accepted in exchange for keeping the CLI free of any dependency on the web app. Web reaches the daemon by fetching `127.0.0.1` directly rather than proxying through Next.js, which is why the daemon grows an opt-in CORS layer, off by default and gated behind `OPENOFFICE_SERVER_CORS_ORIGIN` (commit `7ea874b`).
