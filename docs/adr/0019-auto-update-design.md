# Auto-update design

`openoffice update` replaces the installed binary with a newer Release: the daemon checks GitHub Releases with a cached (TTL) result, the manual command forces a fresh check, the downloaded artifact's SHA256SUMS is verified before anything is swapped, and the previous binary is kept as `.old` until the next run succeeds (on Windows a running exe cannot be overwritten, so a rename dance is mandatory anyway). Both stable and pre-release tags are offered, newest by semver wins — this makes the shakedown release (a pre-release) exercise the same path users will hit. Gated by `update.check`. A bare download-and-swap would be ~30 lines less, but ships whatever GitHub serves without verification and has no way back if the new binary crashes at next launch.
