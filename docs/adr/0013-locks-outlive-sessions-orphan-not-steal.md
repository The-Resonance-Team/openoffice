# 0013 — Locks outlive sessions; a lost lock orphans, never steals

Locks are released only on Accept, Undo, session end (which orphan-marks the session's drafts and releases its locks), or stale override — never on client disconnect. In the daemon model (ADR 0007), sessions persist in SQLite beyond their clients, so "session end" is not a client event; tying lock lifetime to client lifetime would silently drop protection whenever a client vanished mid-edit. Instead, a vanished session's draft becomes an orphaned draft, discoverable by the file-keyed orphan scan and resolvable only through the accept-or-discard prompt — never deleted silently.

A stale-lock override (lock untouched >24h, touched by every mutating command) orphans the previous holder's draft but does not steal the file's editing rights from it: the overridden session's next mutating command fails with a clear error, the agent re-reads the file, and the orphan prompt surfaces the abandoned draft. The overridden session then backs off — it does not re-acquire the lock, because re-acquire would create a stale-override ping-pong between two live sessions. The alternative (release-on-disconnect, re-acquire on re-read) was rejected: it makes a crashed session's unreviewed edits silently unrecoverable, which is the exact loss the draft lifecycle exists to prevent.
